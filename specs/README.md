# Spec-Driven Development (SDD)

All feature changes should start from a written spec in this folder.

## Naming Convention

Use this filename format:

`specs/YYYY-MM-DD_功能描述.md`

Examples:

- `specs/2026-03-03_telegram_draft_streaming.md`
- `specs/2026-03-03_记忆注入顺序调整.md`

## Workflow

1. Create a spec file first.
2. Review and refine the spec until scope and acceptance criteria are clear.
3. Implement code in small commits following the spec.
4. Verify acceptance criteria with tests/manual checks.
5. Update the spec with final notes and status.

## Recommended Spec Structure

1. Background and problem statement
2. Goals and non-goals
3. User stories / use cases
4. API and data model changes
5. Design and implementation plan
6. Risks and rollback plan
7. Acceptance criteria
8. Test plan
9. Progress log
